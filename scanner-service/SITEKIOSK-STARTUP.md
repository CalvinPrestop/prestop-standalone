# Scanner startup through SiteKiosk Online Windows client configuration

The vendor schema confirms that startupApplication.applications is a list of ApplicationConfig entries. This is client configuration, not the page Auto Action.

## Prepared configuration

SiteKiosk-Scanner-StartParameters.json contains only the documented startParameters block. It is not an entire client configuration or a complete ApplicationConfig entry. Merge it into one scanner application's startParameters inside startupApplication.applications. Preserve existing application entries and SiteKiosk-generated defaults for authentication, watchdogConfig and the other application kinds. Do not replace the full client configuration with this file.

Name the entry Prestop scanner. For normal kiosk operation, no visitor authorization should be required for this entry. This application setting is distinct from the Windows runAs account; retain the kiosk account configuration rather than adding admin credentials.

Executable fields:
filePath: C:\Windows\System32\cmd.exe
arguments: /d /c ""C:\PrestopScanner\deployment\win-x86\Start-Scanner.bat" --unattended"
workingDirectory: C:\PrestopScanner\deployment\win-x86
kind: Executable
useShellExecute: false
startAsChildProcess: true
reportStandardOut/reportStandardError: false
verb: empty

Copy the updated Start-Scanner.bat from this project to the kiosk's win-x86 folder. It retains interactive behavior when double-clicked; --unattended skips pause prompts and propagates the EXE's exit code, allowing the watchdog to observe real process exits. There is no detached start command. cmd.exe stays alive while the scanner EXE runs and exits when the service returns.

## Watchdog settings

Preserve generated watchdog fields. Relevant documented properties:
- watchdogConfig.window.noWindow controls whether a start window is created. Keep it false while diagnosing, then test true for background use; a VBS launcher is not needed.
- watchdogConfig.exitBehavior.restartBehavior configures restarts. Use the settings generated by the client editor; do not invent numeric values or enum types.
- watchdogConfig.childProcesses.processesKeepWatchdogAlive and exitBehavior.waitForChildProcesses can keep child processes under observation. Retain a configuration that covers PrestopThalesScanner.exe as well as its cmd.exe parent.
- watchdogConfig.childProcesses.terminateOnStop allows the scanner to stop when its owning kiosk application is stopped, avoiding stale scanner locks during a restart.
- watchdogConfig.process repeats process fields in the schema, but documentation says relevant elements are filled from startParameters by SiteKiosk. Do not override them with conflicting paths.

## Deployment and verification

Remove/disable the earlier scanner Auto Action before enabling client startup. Stop manually started scanner instances. Ensure the kiosk Windows account can read/execute the service and access the installed Thales SDK and USB reader. Deploy/synchronize the client configuration, start SiteKiosk, and check http://127.0.0.1:5081/api/scanner/status in that kiosk session. Test USB scanning and then a complete reboot/logon. If the scanner cannot start under the kiosk account, examine safe SiteKiosk process-start errors without passport data.

The startParameters JSON and batch-file syntax are prepared locally; no client configuration was changed on the test/showroom PC. Exact watchdog configuration and persistence remain unverified until the actual SiteKiosk configuration is available and tested. Share only the scanner startup entry with credentials removed when requesting review.
